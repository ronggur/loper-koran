### Dev iterasi 1 bagian 1a (2026-10-17)

Keputusan rinci (usulan, bisa ditolak di review PR; tidak ada keputusan ROADMAP 5 yang diambil, tidak ada BLOCKED):

- **D-1 Tenggat (`TenggatRute`).** `detik_tenggat = ceil(panjang / 3,0 × 1,15 - 0,000001)` (`TENGGAT_TOLERANSI_DETIK` hanya derau float; 232 -> 89, 236 -> 91, 240 -> 92 dites literal). **Lewat = waktu LEBIH dari tenggat** (+ toleransi): tepat di tenggat (sisa 0) belum lewat. Jam dibuat saat rute disusun (juga tiap Main lagi), maju dengan dt efektif lewat kait baru `AdeganJalan._langkah_waktu` sesudah sepeda digerakkan (jeda dan background = dt 0, beku), dan `hentikan` di langkah garis akhir (langkah itu masih dihitung). Tampilan: detik bulat ke atas untuk sisa ("WAKTU 1:31" di awal rute 236) dan untuk detik lewat ("LEWAT +0:01" 0,01 detik sesudahnya). Status tenggat untuk tip dibaca **saat koran mendarat** (kait `_tenggat_lewat` -> `SkorRute.nilai_koran(..., tenggat_lewat)`).
- **D-2 Tip sesudah tenggat (K-1).** `SkorRute.nilai` mendapat parameter opsional `tenggat_lewat` (bawaan false = perilaku 3B): tip 0, `jumlah_tip` tidak naik; ongkos, skor, combo, terantar, nada combo tetap. Tambah `SkorRute.Keadaan.koin_tip` (bagian koin dari tip) untuk layar hasil.
- **D-3 Radar (`RadarRute`).** Jarak rumah = jarak maju sepeda ke **pusat zona kotak surat** (`ZonaSasaran.maju_kotak_surat`, geometri yang sama dengan zona penilaian). Tampil bila 0 ≤ jarak ≤ 30 (**kedua tepi inklusif**). Vertikal = 1 - jarak/30 (0 atas). `jangkau` = 0 ≤ jarak ≤ jarak tanah lemparan terjauh `ThrowSolver.jarak_ubin(1)` = 5,0 (inklusif; lewat `ThrowSolver` karena tes penjaga melarang angka lintasan di luar solver) dan **hanya rumah pelanggan** (O-10; rumah bukan pelanggan tidak pernah `jangkau` walau aset `ui_radar_bukan_jangkau.png` ada). Penanda di strip: jalur 168 px di dalam bingkai 2 px, tepi atas penanda = round(vertikal × (168 - 6)); penanda jangkau 10x8 berpusat sama (geser -1, -1). Strip ikut sisi dunia, fungsi tidak menerima masukan kidal.
- **D-4 Progres (`ProgresRute`).** Berikutnya = pelanggan belum terantar dengan jarak ≥ 0 terkecil (tepat di samping sepeda masih "di depan"). Pelanggan yang baru dilewati kurang dari atau tepat 3,0 ubin dan belum terantar = **belum** (kosong; masih bisa dikenai lemparan ke belakang). Sesudah rute selesai semua yang belum terantar = terlewat (sama dengan "meleset" layar hasil) dan tidak ada berikutnya.
- **D-5 Arsitektur HUD.** Bagian bersama (tombol jeda, panel bawah kecepatan/stamina/koran, tombol bel, kidal, zona aman) dipindah dari `HudDev` ke `HudDasar` (`scripts/ui/hud_dasar.gd`); `HudDev extends HudDasar` (jalan uji, scene `hud_dev.tscn` tidak berubah, tombol dev Kidal/Bantu dan panel skor dev tetap di jalan uji) dan `HudRute extends HudDasar` (scene rute, `scenes/ui/hud_rute.tscn`). `AdeganJalan._hud` bertipe `HudDasar`. Pewarisan node ini tidak mengulang jebakan D-14 run 3A (yang itu `RefCounted`; tes bebas `resources still in use`). Blok node bersama di `hud_rute.tscn` **disalin** dari `hud_dev.tscn` (bukan scene turunan) supaya `hud_dev.tscn` dan tes jalan uji tidak tersentuh; perubahan panel bawah nanti harus diterapkan di dua `.tscn` (catatan untuk QA/review).
- **D-6 Panel progres** lebar 260 dengan isi samping 6 (bukan 7, `HUD_PROGRES_PAD_X_PX`) supaya 25 × 8 + 24 × 2 = 248 px muat. Label "WAKTU" `TEXT_2` + angka `TEXT`; "LEWAT" dan angkanya `WARN`. Pola kotak 8x8 dari `PolaPiksel.PROGRES_*` (centang garis luar di `OK`, silang `TEXT` di `FAIL`, segitiga garis luar di `ACCENT`, garis putus-putus `TEXT_2` di `UI_PANEL_RAISED`).
- **D-7 Panel kanan atas dan zona aman.** Urutan [koin][skor/combo], skor di slot reputasi di kanan (urutan mock), tepi kanan 28, y 8, tidak dicerminkan saat kidal. Skor dan koin memakai pemisah ribuan dari kunci `HUD_PEMISAH_RIBUAN` ("."). Saat combo putus label `HUD_COMBO` **diganti** label `HUD_COMBO_PUTUS` (`FAIL`) di samping x1.0, jadi lebar panel tidak melompat. Zona aman: `ZonaAman.inset_game` (piksel layar -> game, ke atas, memperhitungkan tepi kosong letterbox), `margin = max(spec, inset)`, dan elemen satu tepi digeser **sama besar** `geser(acuan, inset)` dengan acuan elemen terluar (tepi x: radar 4; atas: area sentuh jeda 4; bawah: 8), karena `max` per elemen akan menumpukkan radar dan tombol jeda. Inset hanya dibaca di perangkat mobile (`OS.has_feature("mobile")`, saat siap dan saat ukuran viewport berubah; ukuran layar = `DisplayServer.window_get_size()`); desktop/editor/headless inset 0 karena persegi aman desktop adalah monitor, bukan jendela. Zona tap bel ikut tombol (`TouchRouter.geser_bel`, `TouchZones.pusat_bel(..., geser_bel)` opsional); zona stick/swipe tidak digeser. Radar bawah tetap y 182.
