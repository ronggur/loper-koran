Fase 1 tetap **tidak** dicentang selesai: butir itu menunggu uji 3-5 orang di HP.

### Keputusan orchestrator (bisa ditolak di review PR)

- **D-1. Umpan balik kecepatan murni dulu.** Logika baru di `scripts/systems/umpan_balik_kecepatan.gd` (`class_name UmpanBalikKecepatan`, `static func`, tanpa node/`Time`/RNG global). Fungsi ini menghitung dari **kecepatan sebenarnya** (dan status rem/meluncur bila dipakai):
  - **Debu roda:** laju pancar (partikel per detik) 0 di bawah ambang (usulan: di bawah santai 3,0 u/d tidak berdebu kecuali rem), naik linear sampai maksimum di ngebut. Saat rem aktif dan kecepatan > 0 ada debu rem (laju tersendiri). Kecepatan 0 = tidak ada debu.
  - **Garis kecepatan:** hanya muncul di atas ambang (usulan: mulai di kecepatan cepat 4,5, penuh di ngebut 6,0). Alpha atau jumlahnya naik linear, dan 0 di bawah ambang.
  - Semua ambang dan laju ada di `Config` (bagian baru "Umpan balik kecepatan (GDD 15)", satu baris per konstanta). NaN, tak hingga, dan negatif aman (hasil 0).
- **D-2. Partikel dari kode, pixel-perfect, hemat.** Node tampil (mis. `scripts/entities/debu_roda.gd`, `garis_kecepatan.gd`) memakai **`CPUParticles2D`** atau `_draw` sendiri, bukan `GPUParticles2D` (lebih aman di Compatibility dan HP kelas bawah; probe render tetap menguji `GPUParticles2D` untuk dicatat). Partikel berupa kotak 1-2 px game dengan warna dari `Palette` (tanpa hex baru di luar `palette.gd`; bila butuh warna debu atau garis, tambahkan token di `palette.gd` dari palet induk `assets/palette/loper_master.gpl` dan catat di `DESIGN_SPEC`/`ART_DIRECTION` sebagai usulan). Arah partikel sejajar jalan (2:1). Tanpa tekstur gradien, tanpa efek layar penuh. Batas jumlah partikel di `Config` (anggaran TECH_PLAN 3.7). Saklar **kurangi efek** (`Config`, bawaan mati) yang mematikan garis kecepatan dan mengurangi debu (rule `ui-scenes`). Belum perlu UI untuk saklar itu.

Autoload `Audio` (TECH_PLAN 3.1).** `scripts/autoload/audio.gd` (`extends Node`), didaftarkan di `project.godot`. **Tidak merujuk autoload lain** (gotcha di rule `gdscript`): data datang dari pemanggil sebagai argumen. Logika keputusan bunyi murni di `scripts/systems/bunyi_sepeda.gd` (`class_name BunyiSepeda`): dari (pose/status, kecepatan sebenarnya, jeda) menghasilkan bunyi loop yang aktif (`kayuh`, `freewheel`, atau tidak ada), `pitch_scale` kayuhan, dan apakah bunyi rem sekali-putar dipicu (**hanya di tepi naik** rem aktif, tidak diulang selama rem ditahan). Pitch kayuhan dari kecepatan sebenarnya, linear per potong: **3,0 → 1,0; 4,5 → 1,15; 6,0 → 1,3** (SOUND_DESIGN 3.2), dijepit 1,0 sampai 1,3. Kayuh dan melambat = loop kayuh; meluncur = loop freewheel; rem = bunyi rem lalu diam; kecepatan 0 tanpa rem = diam. Angka pitch di `Config`. Bus: `default_bus_layout.tres` dengan `Master` → `SFX` → `Sepeda` (SOUND_DESIGN 6; `Ambience`, `Musik`, dan `UI` belum perlu). Jangan menambah musik atau ambience.
